# 薄治理 + 厚测试 治理收口 PLAN（v2）

## 0. 文档定位
- 这是一次最小治理收口，不是治理工程项目。
- 目标是让治理从主战场退回业务护栏，不再挤占功能推进节奏。
- 核心原则：
  - 薄流程：只保留影响业务可信度的硬阻断。
  - 厚测试：主要确定性来自任务级验证、real runtime、Fail->Pass、不回退。
  - 不空转：治理改动必须绑定真实任务试运行。

## 1. 当前问题判断
- 近期返工主因不是业务策略，而是流程一致性失配：
  - 任务定义、目标产物、审计脚本三者口径冲突；
  - 历史产物允许重生但身份语义未制度化；
  - 收尾非原子导致 PR head 与产物绑定漂移；
  - 治理噪音问题被提升为与业务同等级阻断。

## 2. 治理目标（本轮）
- G1：明确阻断项与提醒项，避免治理反噬业务。
- G2：统一历史产物重生语义与口径声明。
- G3：用中度测试自动拦截高频返工点。
- G4：在不增加审批层的前提下保持交付速度。

## 3. 治理策略（拍板版）

### 3.1 仅保留 4 个硬阻断
- B1：范围锁越界。
- B2：主证据自相矛盾（结论与 checks/facts 不一致）。
- B3：高风险任务缺少 real runtime / Fail->Pass / 不回退。
- B4：任务定义、目标产物、审计口径三者冲突。

### 3.2 治理提醒项（默认不阻断）
- notify 文本/排版噪音。
- 元数据展示冗余但不影响业务可信度。
- assemble 展示层冗余信息。
- 不影响主证据结论的历史失败片段残留。

### 3.3 业务结论与治理结论分层
- 业务结论层：
  - 业务目标达成；
  - real runtime 通过；
  - 核心语义不回退。
- 治理结论层：
  - notify 质量；
  - 元数据规范；
  - 报告整洁度。
- 规则：仅影响业务可信度的治理问题才阻断。

### 3.4 历史产物重生语义正式化
- 历史顶层产物若允许后续修复，统一按“重生产物”语义处理。
- 头字段固定三元身份：
  - `Artifact Task ID`
  - `Regenerated By Task`
  - `Generated From Head`
- 任务口径声明二选一：
  - strict equality
  - lineage ancestor
- 禁止再次出现 A/B/C 三套口径并存。

### 3.5 原子封口
- 历史产物重生类任务必须：
  - 代码与脚本修改先完成；
  - 最后一笔提交生成目标产物；
  - 该提交即封口提交；
  - 封口后若继续 push，必须重生目标产物并重审计。
- 若目标产物未在封口提交真实变更，任务直接不通过。

## 4. 厚测试模型（中度，不过度）

### 4.1 任务分层
- 轻任务：
  - 语法检查；
  - 修前/修后各 1 条事实；
  - finalize + gate。
- 中风险任务：
  - 主验证脚本 1 个；
  - real runtime 1 组；
  - 不回退 1~2 条。
- 高风险任务：
  - Fail->Pass；
  - 连续 real runtime 样本；
  - 真值链对账；
  - 护栏验证 2~3 个。

### 4.2 本轮仅接入 4 个自动检查
- T1：任务口径声明 vs 审计口径一致性。
- T2：目标产物头字段完整性。
- T3：目标产物在 PR diff 中可读。
- T4：头字段关系符合声明：
  - strict -> 必须等于；
  - ancestor -> 必须为祖先关系。

## 5. 执行任务拆分（固定三任务）
- 260406_001：治理定义最小统一
  - 输出：
    - 4 个硬阻断 + 提醒项清单；
    - 业务结论/治理结论分层规范；
    - strict/ancestor 声明规范；
    - 三元身份字段规范；
    - 语义变更必须开新任务规则。
- 260406_002：轻门禁 + 中度测试接入
  - 输出：
    - T1~T4 自动检查；
    - gate 子检查与本地执行入口；
    - 不新增审批动作。
- 260406_003：绑定下一条真实任务试运行
  - 不做独立空试点；
  - 在下一条真实任务中演练全链：
    - 任务定义 -> 目标产物 -> 审计 -> gate -> PR 验收；
  - 输出一份简短治理验收报告（有效性 + 节奏影响）。

## 6. 验收标准（治理收口是否成功）
- A1：同类口径冲突问题可一次拦住。
- A2：业务任务不再被纯展示/噪音问题频繁阻断。
- A3：单任务负担可控，无新增审批层。
- A4：真实任务中定义/产物/审计三者一致。

## 7. 非目标（本轮不做）
- 不改业务策略语义（stop/window/completed/today-7d-30）。
- 不做大规模测试框架重构。
- 不引入复杂发布编排或多层审批流程。
