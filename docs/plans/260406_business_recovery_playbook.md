# 首条业务任务恢复执行手册（260406_005）

## 1. 目的
- 在治理收口（260406_001~004）后，恢复业务任务推进，并保持治理边界稳定。

## 2. 适用范围
- 适用于后续首条及同类业务任务（BTCQDD 域）。
- 以“薄流程 + 厚测试”为默认策略执行。

## 3. 业务任务立项模板
- 必填：
  - 业务目标（可量化）
  - 风险级别（轻/中/高）
  - 口径声明（`strict equality` 或 `lineage ancestor`）
  - 目标产物（可直接读取路径）
- 必选验证：
  - doc-contracts
  - gate-light
  - 对应风险级别的最小测试集

## 4. 运行流程（执行顺序）
- Step 1：先落任务定义（目标/边界/口径声明）。
- Step 2：实现业务改动，禁止在同任务中切换口径。
- Step 3：生成目标产物并进行审计。
- Step 4：运行 gate-light 与 doc-contracts。
- Step 5：提交提审，结论拆分为“业务结论 / 治理结论”。

## 5. 最小测试矩阵
- 轻任务：语法 + 1条修前/修后事实 + gate。
- 中风险：主验证脚本 + 1组 real runtime + 1~2 条不回退。
- 高风险：Fail->Pass + 连续 real runtime + 真值链对账 + 护栏验证。

## 6. 失败处理
- 若触发 4 硬阻断之一：
  - 立即停止扩面改动；
  - 新建回修任务；
  - 保持口径不漂移。
- 若仅触发提醒项：
  - 记录提醒并继续业务推进；
  - 在下一轮清理，不阻断主结论。

## 7. 交付要求
- 任务文件、目标产物、审计脚本三者口径一致。
- 结论必须包含：
  - 业务目标是否达成
  - 是否引入治理阻断
