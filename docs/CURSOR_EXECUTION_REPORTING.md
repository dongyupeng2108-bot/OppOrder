# BTCQDD｜Cursor 执行与回报规范（防幻觉 / 防伪造完成）

项目长期执行规范；与 [`CURSOR_REVIEW_MERGE.md`](CURSOR_REVIEW_MERGE.md)（审核与合并）配合使用。

---

## 1. 总原则

- 可以快做，但**不能模糊记账**。
- 任何「完成」声明，必须**可核验、可拆分、可打假**。

---

## 2. 完成类型必须分开写

每次回报，先把本次结果按类型分类，**只能**使用下面几类：

| 类型 | 含义 |
|------|------|
| **DOC** | 文档完成 |
| **UI** | 前端展示完成 |
| **TEST** | 测试脚本 / 测试稳定性完成 |
| **CODE** | 代码改动完成 |
| **RUNTIME** | 真实运行闭环完成 |

**禁止**把这些混成一句「任务完成」。

**例子**

- **错误**：已完成 P0  
- **正确**：  
  - DOC：已补 P0 工作流文档  
  - TEST：已新增最小校验脚本  
  - RUNTIME：**未完成**，尚未验证真实运行问题消失  

---

## 3. 每条完成声明必须带证据类型

每条声明后必须标明证据来源，**只能**用这些标签：

| 标签 | 含义 |
|------|------|
| **CODE** | 代码位置 |
| **TEST** | 测试结果 |
| **API** | 接口返回 |
| **DOM** | 页面文本事实 |
| **RUNTIME** | 真实运行事实 |
| **DOC** | 文档内容 |

**硬规则**

- **DOC 不能冒充 RUNTIME**  
- **TEST 不能自动冒充业务正确**  
- **CODE 改了，不等于问题已修复**  
- **本地通过，不等于真实运行闭环**  

---

## 4. 禁止使用模糊完成词

以下词**不能单独出现**：

- 已完成  
- 已修复  
- 已闭环  
- 已解决  

除非后面紧跟这三项：

1. **完成类型**  
2. **最小事实块**  
3. **未覆盖边界**  

**例子**

- **正确**：已完成（UI）— 证据：DOM + API — 未覆盖：未验证真实运行  
- **正确**：已修复（TEST）— 证据：单测 3 连跑 PASS — 未覆盖：未证明业务链真实无回归  

---

## 5. 并行执行可以，但并行糊账不行

可以一次完成多个轻任务，但回报**必须拆开写**：

- **已完成**：哪些是文档项、哪些是 UI 项、哪些是测试项  
- **未完成**：哪些只是铺底、哪些尚未形成业务闭环、哪些还缺真实运行验证  

**禁止**把「补文档 + 写脚本 + 改一处 UI」统一表述成「一个业务任务已闭环」。

---

## 6. 轻任务 / 重任务分流

### 轻任务

适用于：UI / 文案 / 布局；文档；clean PR；纯测试脚本稳定性；只读审计。

回报**最少**需写：**目标**、**范围**、**完成类型**、**最小事实块**、**未覆盖边界**。

### 重任务

适用于：真实运行 bug；生命周期 / 状态机；订单语义；模拟 vs 实盘一致性风险；版本测试主链修复。

回报**必须**写：**根因**、**修复点**、**完成类型**、**最小事实块**、**真实运行是否复验**、**未覆盖边界**。

---

## 7. 固定回报格式

每次回报统一按下面格式：

### 1）本次完成项

- 项目名：  
- **完成类型**：DOC / UI / TEST / CODE / RUNTIME  
- **证据类型**：CODE / TEST / API / DOM / RUNTIME / DOC  
- **最小事实块**：……  

### 2）本次未完成项

- 哪些只是铺底  
- 哪些不算闭环  
- 哪些仍需后续任务  

### 3）风险与边界

- 哪些结论是**事实**  
- 哪些仍是**推断**  
- 哪些**未做验证**  

### 4）下一步建议

- 建议下一条**只做什么**  

---

## 8. 本项目特别规则

- **不要求截图作为主证据**；优先：**DOM 文本**、**API 返回**、**测试结果**、**日志**、**最小事实块**。  
- **测试失败不等于业务失败** — 先区分：业务 bug / 测试资产 bug / 两者都有。  
- **文档完成不等于业务完成** — 文档、契约薄表、示例 JSON、说明脚本，都**不能**冒充真实闭环。  
- **受控样本通过不等于真实运行已修复** — 高风险问题仍需 **real runtime** 复验。  

---

## 9. 一句话版

> 可以快做，但每个「完成」都必须标明它到底是**文档完成、UI 完成、测试完成**，还是**业务 / 真实运行完成**；不同类型的完成，**不能互相冒充**。

---

## 10. 记账用语（禁止用 Phase / todo「完成」指代文档交付）

**禁止**单独使用「Phase 完成」「todo completed」「阶段已闭环」来指代「只写了文档」或「只跑了辅助脚本」。

统一改用下面三句（可并列出现）：

| 用语 | 含义 |
|------|------|
| **文档项完成** | 说明、索引、审计稿、契约薄表等**文档交付物**已按任务写入（完成类型仍标 **DOC**）。 |
| **测试辅助完成** | 某次 `verify_*` / 结构校验 / 快照跑通或已记录结果（完成类型 **TEST**）；**不**自动等于业务正确。 |
| **业务闭环未完成** | 尚未满足任务书要求的 **RUNTIME** 复验、Fail→Pass 于真实主链、或 Owner 未签收时，**必须**写明；**禁止**用前两项冒充此项已达成。 |

**错误示例**：「Phase C 已完成」「todo 全绿」。  
**正确示例**：「文档项完成：`REGRESSION_xxx.md`；测试辅助完成：`verify_anchor_bounds_lifecycle` 本地 exit 0；**业务闭环未完成**：未填 real runtime 样本表。」
