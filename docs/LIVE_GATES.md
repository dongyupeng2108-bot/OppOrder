# Live 实盘与自动化（闸门说明）

**状态**：**未来阶段**；在 Paper 全链与版本测试 **稳定可复验** 之前，本文件仅作 **闸门与范围** 约定，**不触发任何实盘代码路径的默认开启**。

## 前提（与总体计划一致）

- [`PROJECT_MASTER_PLAN.md`](../rules/rules/PROJECT_MASTER_PLAN.md) G1–G3 收口；P0/P1 高风险不变量可持续回归。
- [`PROJECT_RULES.md`](../rules/rules/PROJECT_RULES.md)：禁止擅自增加「自动实盘推进」能力。

## 建议子闸门（顺序由 Owner 最终裁定）

| 顺序 | 闸门 | 说明 |
|------|------|------|
| G-L1 | 连接与只读 | API/WS 连通、鉴权、费率与限制可读；**不下单**或仅最小权限 |
| G-L2 | 显式开关 + 人工确认 | 首笔真实订单需明确操作与限额 |
| G-L3 | 限额与熔断 | 单笔/单日、最大回撤、连续失败停机等 |
| G-L4 | 审计与日志 | 与 paper 可对账的订单 id、请求/响应摘要 |
| G-L5 | 受控自动化 | 在 G-L1–G-L4 长期稳定后，再评估无人值守 |

## 与五模块的关系

- **执行引擎**：Live 与 Paper 分叉应在 **执行适配层** 清晰隔离，且语义可对齐部分需文档化。
- **策略输入**：Live 下延迟、断线、重试与 paper 不同，需单独验收。
- **版本测试**：Live 通常**不**与现有 `verify_*` 混跑同一断言；需独立策略与沙盒。
