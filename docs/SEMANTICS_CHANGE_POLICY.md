# 高风险口径变更门槛说明（C1-4）

## 文档定位

- 本文档用于定义“高风险语义改动 vs 普通模块内改动”的门槛与最低同步要求。
- 本文档是后续统一同步进三大文档的输入稿；本任务不改三大文档。

## 分类标准

### A. 高风险语义改动

满足任一即归类为高风险：

- 触碰以下主链对象之一：
  - `anchor_btc`
  - `upper_bound / lower_bound / bounds_ready`
  - ATR 缺失行为
  - `current / active / last`
  - `filled_total`
  - PNL 分区口径
  - order scope / status
  - readiness / runtime 语义
- 改变上述对象的生产者、对外暴露字段、验收依据或跨模块边界语义。

### B. 普通模块内改动

同时满足以下条件才可归类为普通：

- 不触碰上述高风险对象；
- 不改变主链语义生产者与对外口径；
- 改动影响限定在模块内部实现或展示细节。

## 高风险改动的最低同步项

高风险语义改动至少同步以下内容：

- 总口径文档：`docs/BTCQDD_CORE_SEMANTICS.md`
- 模块契约：`docs/CONTRACT_*.md`（受影响模块）
- 绑定图：`docs/SEMANTICS_BINDING_MAP.md`
- verify / runtime 证据：对应 `verify_*.mjs` 结论与 runtime 采样证据

同时满足两条硬约束：

- 代码改了但未同步口径/契约/绑定图，不得视为闭环。
- 文档改了但无代码/API/verify/runtime 对应绑定，也不得视为已工程化掌控。

## 验收门槛

### 必须整链验收的情况

- 任一高风险语义改动；
- 变更跨越“输入 -> 引擎 -> API/UI -> verify/runtime”任一关键连接；
- 影响 order scope / status、readiness 或 runtime 语义判定。

### 可仅模块验收的情况

- 明确归类为普通模块内改动；
- 且不影响主链语义、对外口径与绑定关系；
- 且已有受影响模块内验证证据。

## 最小执行规则

- 先分类（高风险/普通），再决定验收深度（整链/模块）。
- 对高风险改动，缺少任一最低同步项时，状态必须记为“未闭环”。
- 若分类存在争议，默认按高风险处理并执行整链验收。
