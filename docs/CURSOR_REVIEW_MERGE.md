# BTCQDD｜Cursor 审核与合并流程

本文档约束 **Cursor Agent** 在本仓库内的权限与回报口径；与 [`rules/rules/WORKFLOW.md`](../rules/rules/WORKFLOW.md) 并行，**合并决策权**以本文为准。

---

## 0. 总原则

1. **可以**：本地完成修改、本地验证、提交 commit、推送分支、创建 PR。
2. **不可以**：**自行 merge（合并）** 到受保护分支或任何未经 Owner 明确授权的目标分支。
3. **是否合并**：**仅由 Owner 决定**。
4. **表述**：不得把「已提交 / 已开 PR / 已本地验证」说成「**已完成合并**」或等同于「已上线/已闭环」。

---

## 1. 流程分界线

Agent 最多推进到：

> **本地修改完成 → 本地验证 → 提交 commit → push 分支 → 创建 PR → 回报等待审核**

到此**必须停下**。  
不得自行执行 merge；不得自行将「待审核」视为已收尾。

---

## 2. 回报必须分三层写清

每次回报须区分：

### A. 本地完成

- 代码/文档/脚本已在本地改完  
- 本地验证已完成（命令与结果摘要）

### B. PR 完成

- 分支已推送（若已执行 push）  
- PR 已创建（附可访问链接，若平台已生成）  
- CI / checks **当前状态**（通过 / 失败 / 未跑）

### C. 合并状态（只能三选一）

- **未合并，等待 Owner 审核**  
- **已获 Owner 明确批准，可合并**（仅当 Owner 明确说出）  
- **已由 Owner 合并**（仅当 Owner 告知或远程分支状态已确认）

Agent **不得**自行将状态写成「已合并」，除非 Owner 明确告知已合并。

---

## 3. 轻任务审核流程

适用于：文档；UI/文案/布局；clean PR；纯测试脚本稳定性；只读审计。

1. 本地完成  
2. 给出最小事实块（DOM/接口/日志/测试结果等）  
3. 创建 PR  
4. 回报：**完成类型**、**证据类型**、**PR 链接**、**CI 状态**、**等待 Owner 审核**  
5. **停止**，不自行 merge  

---

## 4. 重任务审核流程

适用于：真实运行 bug；生命周期/状态机；订单语义；模拟 vs 实盘一致性风险；版本测试主链修复。

1. 先定位  
2. 再修复  
3. 再本地验证  
4. 若任务要求，做真实运行复验  
5. 创建 PR  
6. 回报：**根因**、**修复点**、**最小事实块**、**PR 链接**、**CI 状态**、**等待 Owner 审核**  
7. **停止**，不自行 merge  

---

## 5. 合并前：即使条件齐全也不可自合并

在未得到 **Owner 明确许可** 前，即使以下全部成立，Agent **仍不得自行 merge**：

- 本地验证通过  
- `npm test` / verify 通过  
- Gate Light / CI 通过  
- PR 内容完整  
- 主观判断风险很低  

只能说明：**PR 已具备审核条件**，**不等于** Agent 可自行合并。

---

## 6. 回报格式（固定）

每次提交 PR 后的回报建议采用：

### 本次完成项

- 项目名：
  - **完成类型**：DOC / UI / TEST / CODE / RUNTIME  
  - **证据类型**：CODE / TEST / API / DOM / RUNTIME / DOC  
  - **最小事实块**：……

### PR 状态

- **分支**：……  
- **Commit**：……  
- **PR**：……（链接）  
- **CI / checks**：……

### 当前状态

- **未合并，等待 Owner 审核**（默认）

### 未覆盖边界

- ……

---

## 7. 禁止事项

1. 禁止自行 merge。  
2. 禁止把「已开 PR」写成「任务已完成」或「已闭环」（除非文档明确定义仅为 PR 阶段完成）。  
3. 禁止把「本地验证通过」写成「业务已闭环」。  
4. 禁止在未审核前以「收尾」为由删除分支或关闭 PR（除非 Owner 要求）。  
5. 禁止因「文档/轻任务/低风险」而自行合并。  

---

## 8. 角色分工（修正口径）

> **Agent 负责做到「可审核」；Owner 负责决定「是否合并」。**
